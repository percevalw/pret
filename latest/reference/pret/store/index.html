    Store [source]

    Live view of a mapping or list of a Store, edits are saved as Store operations.

    Views compare by identity, the same value keeps the same view, so a view captured before an insertion in its parent list keeps following its value.

    revision property [source]

    Return the latest saved revision number, including edits saved by other processes

    metadata property [source]

    Return the metadata saved with this Store

    path [source]

    Return the operation path of this value, refusing edits once it was removed from the Store

    edit [source]

    Apply one operation on this value within the current Store transaction

    wrap [source]

    Return the view of a child node, the DataFrame of a reference, or a plain value

    to_py [source]

    Return a plain copy of this value, DataFrames stay references

    StoreDict [source]

    Bases: Store, MutableMapping

    Mapping of a Store, see Store

    List of a Store, see Store

    index_of [source]

    Return the non negative position of an index, refusing positions outside the list

    move [source]

    Move the item at start before the item at end, both positions taken before the move. The view of the moved item no longer follows it.

    StoreDoc [source]

    Keep the live values of a Store and save their edits as operations in its StoreDatabase.

    edit_transaction groups Python edits, DataFrame edits and browser requests in one SQLite transaction, its operations and their inverses are saved together with the table changes. apply_browser_edit moves browser operations over the commits they did not see, refresh loads the commits saved by other processes. Each browser page has an undo history of its revisions, reversed selectively by reverse_action.

    ATTRIBUTE DESCRIPTION
    root

    Live tree, a MapNode with the user value under "data", the Store "metadata" and its sync "id"
    database

    StoreDatabase saving the operations, the current values and the DataFrame tables

    TYPE: StoreDatabase | None

    revision

    Latest revision applied to root
    histories

    Undo and redo revisions per browser page origin
    recording

    Operations and inverses of the open transaction, replayed backwards if it fails

    proxy [source]

    Return the view of a node, the same view each time

    browser_data [source]

    Send the current values and table copies, or the commits after a revision, to a browser

    attach_dataframe [source]

    Return the DataFrame this Store keeps for an assigned DataFrame.

    Arrow tables and tables of another Store are copied into this Store database, named after the Store key. Spark and Ibis sources stay queries against their source.

    register_dataframe [source]

    Register a DataFrame so browser methods and Store edits can find it by resource ID

    on_update [source]

    Call fn after each saved Store change, the server manager then notifies browsers

    apply_local [source]

    Apply an operation of the open transaction to the live tree, recording it and its inverse

    edit_transaction [source]

    Group Python, DataFrame and browser edits so SQLite saves them together as one revision.

    If the block raises, the live values are restored by applying the recorded inverses, nothing is saved, and the uncommitted DataFrames are forgotten. Browser page origins, including their awaited Python callbacks, record the revision in the page undo history.

    rollback [source]

    Restore the values the failed transaction changed and forget the DataFrames it created

    publish [source]

    Record the latest applied revision, then notify browsers and Python subscribers

    refresh [source]

    Apply the commits saved by other Python processes, in revision order, before the next Store operation

    browser_ops [source]

    Check the operations of a browser request, which may only change the user value and refer to known tables

    committed_ops [source]

    Return the operations committed after a revision, each with the origin of its commit

    reverse_action [source]

    Undo or redo the latest action of a browser page, called by apply_browser_edit.

    Table cells are reversed selectively by StoreDatabase.reverse, and ordinary values by the inverse operations of the action moved over the later commits, skipping values another page changed since. The reversal is itself recorded in the opposite list, for redo or a new undo.

    apply_browser_edit [source]

    Handle a browser request, returning the saved result if the same request was already handled.

    Browser operations are moved over the commits after the request base revision, an operation whose target a newer commit removed or replaced rejects the whole request as a conflict.

    dataframe_edit [source]

    Save a DataFrame edit in its enclosing transaction or acknowledge a standalone request

    watch async [source]

    Check periodically for edits saved by other processes while this Store is still in use

    StoreDatabase [source]

    Store the values and edit log of one Pret Store in SQLite.

    Each _pret_changes row holds the operations of one revision on the ordinary values, their inverses and the SQL changes of its DataFrame tables. A transaction saves them together with one revision number and request ID. _pret_state holds the ordinary values as JSON at its revision, it is rewritten once the operations logged since exceed a tenth of its size and when the database closes, read_state replays the operations after it. The log records which cells changed and who changed them, so undo can preserve another user's edits and a repeated browser request can return its earlier result.

    build_store attaches this database to StoreDoc, which sends updates to browsers after saving. SQLiteDataFrameProvider fetches and edits the table rows. DataFrame queries can also use an in memory database without a live document.

    Parameters

    PARAMETER DESCRIPTION
    path

    File to open, or :memory: for a Store that is not saved to disk

    DEFAULT: ':memory:'

    readonly

    Open an existing file without writing to it, used by load_store_snapshot

    DEFAULT: False

    ATTRIBUTE DESCRIPTION
    ops, inverse

    Operations of the current transaction and their inverses, in the order they undo, set by StoreDoc
    values

    Live values after the current transaction, set by StoreDoc so _pret_state is rewritten without replaying
    table_changes

    APSW session recording SQL row changes for undo, closed when the transaction ends

    TYPE: Session | None

    update_views [source]

    Keep one SQL view per top-level Store DataFrame, named after its key, for plain SQLite readers.

    keys maps each top-level Store key to its DataFrame resource ID. A key that clashes with another SQLite object, a reserved prefix or another key in a different case gets no view.

    read_state [source]

    Return the current ordinary values and their revision, _pret_state with the operations logged after it

    write_state [source]

    Rewrite _pret_state at the latest revision, from the live values when given or by replaying the log

    transaction [source]

    Save operations, table edits and one acknowledgement in one SQL transaction.

    Nested calls join the outer transaction. If a block raises, none of its SQL changes are saved, StoreDoc restores the live values.

    browser_data [source]

    Send Arrow tables, or the operations and row changes of the commits after a revision.

    Browsers call this once without a revision, receiving the current values and, for complete copies, every table, then with the last applied revision. Byte offsets identify Arrow streams in the response buffer. Newly created tables are copied at the final revision, so their earlier row changes are excluded from this response. With watched resource IDs and row IDs, only subscribed row values are sent, alongside summaries for query maintenance.

    acknowledgment [source]

    Reconstruct the transaction reply so browser retries do not repeat committed edits.

    Row identities are a scalar for one row, a list for a DataFrame batch or grouped lists for a browser transaction that edits several DataFrames.

    add_dataframe [source]

    Copy Arrow batches into a new SQL table and return the provider used by DataFrame queries

    reverse [source]

    Undo table edits for one browser action while keeping later edits by other users.

    StoreDoc.reverse_action calls this for undo and redo. Only cells and rows actually changed by this call are recorded, so redo cannot reapply an edit that undo skipped.

    close [source]

    Bring _pret_state up to date for plain SQLite readers, then close the connection

    is_marker [source]

    Tell whether a Store value is the reference to a DataFrame saved in the Store database

    adopt [source]

    Turn a JSON value into nodes of the live tree under parent, existing nodes are moved back unchanged.

    store_ops.apply calls this for operation values, and for removed nodes when a rollback restores them, so proxies captured before the rollback still show the same values.

    node_path [source]

    Return the operation path of a node, or None once it was removed from its Store

    prepare_value [source]

    Return the JSON value saved for a value assigned to a Store, DataFrames become references to their table.

    Store proxies are copied, their DataFrames are attached to this Store as well.

    store_mutation [source]

    Run a mapping or list edit inside one Store transaction, so several operations are saved together

    dataframe_keys [source]

    Map top-level Store keys to the resource IDs of their DataFrames, for StoreDatabase.update_views

    write_transaction [source]

    Take the SQLite write lock before checking table versions and undo SQL changes if the block raises

    rebuild_proxy [source]

    Return the view at a path of a Store, the browser loader rebuilds Store views this way

    rebuild_doc [source]

    Called by the browser loader to rebuild a Store document, the Python body never runs

    create_store [source]

    Create a new store that can be used to store and synchronize data between various components of the app, between a server and its clients, or between different processes (or across multiple runs of the app) using a file.

    Parameters

    PARAMETER DESCRIPTION
    data

    Initial data to store in the document. It can be a dictionary, list, or any simple value. If a callable is provided, it will be called to get the initial data. This can be useful if the initial data is expensive to create, and you only want to create it if the store is actually being initialized with it (e.g. when using file synchronization and the file doesn't already exist).
    dataframe_sync

    Paged queries by default, or full to copy every SQLite table to connected browsers

    DEFAULT: 'paged'

    dataframe_max_bytes

    Required positive Arrow byte limit for the initial full copy download

    DEFAULT: None

    sync

    There are three options for this parameter:

    • If false, this store will not be synchronized between a server and its clients. This can be useful for local-only stores, like style management.
    • If true, the store will be synchronized between a server and its clients. Any changes made to the store will be sent to the server and vice versa.
    • If a path is provided, the store will be synchronized with the file at this path. Any changes made to the store will be written to the file, and any changes made to the file will be read into the store. This can be useful if you want to persist the store to disk or share it between different processes (think servers or kernels).

    TYPE: Optional[Union[bool, str, PathLike]] DEFAULT: None

    build_store [source]

    Load the Store values and DataFrame tables of a database, creating them on a new database

    read_legacy_file [source]

    Read the sync ID and Yjs updates of a Store file in the released append format.

    The file starts with a 36 character sync ID followed by updates, each prefixed by its 4 byte little endian size. A truncated last record is ignored.

    read_legacy_values [source]

    Return the sync ID, value and metadata of a released append format file, decoded with pycrdt

    convert_legacy_file [source]

    Replace a released append format file by a SQLite Store file with the same values and sync ID.

    build_store calls this once when opening such a file. The original file is kept next to it with a .legacy suffix, processes still using it no longer share edits.

    copy_store_value [source]

    Copy Store values before write_store saves them to a new file.

    Parameters

    PARAMETER DESCRIPTION
    materialize

    If False, copy mappings and lists but leave DataFrames for the saving thread to collect

    DEFAULT: True

    save_store [source]

    Save this Store to a new file and return a Store connected to that file

    write_store [source]

    Write the Store to a new file, keeping its edit log when saving the whole Store.

    save_store calls this directly. Server callers can also pass values prepared by copy_store_value to collect large DataFrames in a separate thread.

    load_store [source]

    Open a saved Store, changes are saved back to the same file

    Parameters

    PARAMETER DESCRIPTION
    dataframe_sync

    Paged backend queries or full browser copies of the Store tables

    DEFAULT: 'paged'

    dataframe_max_bytes

    Required positive Arrow byte limit when dataframe_sync is full

    DEFAULT: None

    load_store_snapshot [source]

    Read ordinary Store values from a file without subscribing to later changes.

    Parameters

    PARAMETER DESCRIPTION
    path

    Store file previously created with file synchronization or save_store

    TYPE: Union[str, PathLike]

    metadata

    Return the metadata saved with the Store instead of its ordinary values

    DEFAULT: False

    RETURNS DESCRIPTION
    Any

    A copy of the values as Python mappings, lists and scalars, DataFrames become in memory copies of their rows

    subscribe [source]

    Call a function after each saved change of a Store value.

    The callback receives the operations of the change under this value, with paths relative to it, eg [{"op": "set", "path": [0, "done"], "value": True}], and the change {"revision", "origin", "kind"}.

    Parameters

    PARAMETER DESCRIPTION
    store

    The value to watch

    TYPE: Store

    callback

    The function to call, subscribe returns a decorator when omitted

    TYPE: callable DEFAULT: None

    RETURNS DESCRIPTION
    callable

    A function that stops the notifications

    transact [source]

    Group multiple store mutations into a single transaction.

    Use this as a context manager to batch several writes so subscribers and synchronization hooks are triggered once after the block completes.

    Parameters

    PARAMETER DESCRIPTION
    store

    Store value whose document transaction should be used

    TYPE: Store

    origin

    Origin recorded with the change, browser page origins enter the page undo history

    TYPE: Any DEFAULT: None

    YIELDS DESCRIPTION
    dict

    The Store action being saved, with its request ID, origin and revision number
