    pret

    DataFrame [source]

    Tabular data that can be placed in a PRET Store and displayed by widgets.

    Create one from rows, an Arrow or pandas table, or a Spark or Ibis expression. The provider fetches rows from that source and applies edits when supported. Adding an Arrow or pandas DataFrame to a Store copies its rows into the SQLite database of that Store. Spark and Ibis expressions remain queries against their source until explicitly collected, for example by save_store.

    Parameters

    PARAMETER DESCRIPTION
    records_or_arrow

    Rows, a column mapping, an Arrow or pandas table, or a Spark or Ibis expression

    DEFAULT: None

    provider

    DataFrameProvider subclass used instead of records_or_arrow

    TYPE: DataFrameProvider | None DEFAULT: None

    resource_id

    Internal table ID, supplied by PRET when reopening or copying a Store

    DEFAULT: None

    ATTRIBUTE DESCRIPTION
    provider

    Object that reads and optionally edits the underlying data
    store_doc

    Containing Store document, or None before the DataFrame is added to a Store

    describe async [source]

    Return column types, row count and supported operations so widgets can configure their fields

    query async [source]

    Fetch a page of rows for tables, forms and annotation widgets.

    The provider filters and sorts the full source before selecting the requested page. The response includes Arrow bytes and counts used by the table scrollbar.

    Parameters

    PARAMETER DESCRIPTION
    options

    Filters, sort columns, columns to return, offset and limit, with optional row ID lookups

    DEFAULT: None

    RETURNS DESCRIPTION
    BinaryPayload

    Arrow bytes with the filtered row count, Store revision number and any requested row positions

    apply_edit async [source]

    Apply a widget edit through the Store transaction, or through the source when it handles its own edits

    get_changes_after_revision async [source]

    Tell a widget whether its displayed rows need to be fetched again

    materialize [source]

    Fetch all rows as an Arrow table for saving or standalone browser export.

    For Spark or Ibis sources this runs the query and collects its full result. Optional max_rows and max_bytes entries in bounds limit the exported data.

    with_columns [source]

    Return a DataFrame with missing columns filled from constants or a function called for each row

    submit_edit [source]

    Save a DataFrame.insert, update or delete call with the latest revision number as its base

    insert [source]

    Add one row from a mapping of column names to values

    update [source]

    Change one row matching the identity column values, for example identity=dict(id=3)

    delete [source]

    Remove one row matching the identity column values, for example identity=dict(id=3)

    __reduce__ [source]

    Send this DataFrame to a browser using the connection mode of its Store.

    Connected Stores send Python methods for queries and edits, or only a flag for tables copied in full to the browser. Browser only Stores send the Arrow rows.

    DataFrameProvider [source]

    Bases: ABC

    Read a table for DataFrame widgets, with optional saving and editing support.

    Subclasses implement describe and query. These methods can return their result directly or asynchronously, DataFrame awaits either form. A query returns an Arrow table containing the requested rows, not serialized bytes or SQL text.

    Providers that support save_store also implement synchronous materialize. Editable providers implement apply_edit and report edit capability in describe.

    apply_ibis_filter [source]

    Apply widget filters and conjunctive relation filters before source counting and paging.

    get_related_table maps a DataFrame resource_id to its lazy source table, an Ibis Table object. For a relation filter, restrict that related table first and keep calling-table rows whose key occurs in it. The semi join keeps each calling-table row once even if related keys repeat.

    use_dataframe_view [source]

    Subscribe a browser component to a DataFrame query view.

    The view shows the scope of the DataFrame, the rows shared by all its widgets in the page, filtered and sorted for this component. When no scope is set, the hook loads the whole table. This hook exposes a rowSource for loaded data, the preceding rowSource while the view changes, and the DataFrame description, loading message, and error. It releases its view when the component unmounts. Pass arguments by position, the browser function takes no keywords.

    To show related tables together, such as notes and their entities, pass load=False and set the scopes from a component effect. await dataframe.fetchScope(filter) queries the scope of a filter without showing it, dataframe.setScope(scope) shows it in every widget of that DataFrame. Fetch the scopes of all related tables first, then set them one after the other.

    Parameters

    PARAMETER DESCRIPTION
    dataframe

    Client DataFrame supplied by the component Store
    filter

    PRET filter expression evaluated by the DataFrame provider

    DEFAULT: None

    primary_key

    Column used to locate rows selected by the factory

    TYPE: str | None DEFAULT: None

    sort

    List of column and direction mappings

    DEFAULT: None

    load

    Load the whole table when no scope is set, False when the component sets scopes itself

    TYPE: bool DEFAULT: True

    RETURNS DESCRIPTION
    object

    rowSource for the current query, previousRowSource during a view change, description, loading message and error for the component to render

    use_effect [source]

    The useEffect hook allows you to perform side effects in function components. Side effects can include data fetching, subscriptions, manually changing the DOM, and more.

    The effect runs after every render by default. If dependencies are provided, the effect runs whenever those values change. Therefore, if dependencies is an empty array, the effect runs only once after the initial render.

    Parameters

    PARAMETER DESCRIPTION
    effect

    A function containing the side effect logic. It can optionally return a cleanup function, an async function starts its work and has no cleanup.

    TYPE: Callable DEFAULT: None

    dependencies

    An optional array of dependencies that determines when the effect runs.

    TYPE: Optional[List] DEFAULT: None

    use_event_callback [source]

    Store a callback function that can be updated without re-rendering, and return a stable wrapped function that will always call the latest callback.

    This can be used in two ways:

    1) With dependencies (decorator factory):

    @use_event_callback([dep1, dep2])
def the_callback(*args, **kwargs):
    ...

    2) or without

    @use_event_callback  # (equivalent to @use_event_callback([]))
def the_callback(*args, **kwargs):
    ...

    The optional dependencies behave like the dependency array of React's useCallback. If an empty list is provided, the wrapped callback will be called only once (when the component is mounted). If None is provided, the wrapped callback will be called on every render.

    Warning

    Do not use this hook if the rendering of the component depends on the callback function.

    Parameters

    PARAMETER DESCRIPTION
    arg

    Either the callback itself (bare decorator / direct call), or a dependency list when used as @use_event_callback([...]).

    TYPE: Optional[Any] DEFAULT: None

    RETURNS DESCRIPTION
    Callable

    The wrapped callback function (or a decorator that returns it).

    use_imperative_handle [source]

    Safely binds a custom value or API to a parent's ref.

    Unlike manually setting ref.current, this hook automatically handles the lifecycle: it updates the ref when dependencies change and cleans it up (resets it to None) when the component unmounts.

    Use this to expose specific methods (like focus or reset) to a parent, rather than giving them direct access to internal DOM nodes.

    Example

    from pret import component, use_ref, use_imperative_handle
from pret.react import button, div, input


@component
def CustomInput(handle):
    # 1. The internal ref connects to the actual DOM element
    internal_input_ref = use_ref(None)

    # 2. We define what the parent is allowed to see/do and attach
    # that API to the handle passed down from the parent
    use_imperative_handle(
        handle,
        lambda: {
            "reset_and_focus": lambda: (
                setattr(internal_input_ref.current, "value", ""),
                internal_input_ref.current.focus(),
            )
        },
        [],
    )

    return input(placeholder="Type here...", ref=internal_input_ref)


@component
def App():
    # The parent creates a ref
    input_controller = use_ref(None)

    def on_click(event):
        # The parent calls the custom method defined in the child
        input_controller.current.reset_and_focus()

    return div(
        # Pass the ref as a regular prop named 'handle'
        CustomInput(handle=input_controller),
        button("Reset Form", onClick=on_click),
    )

    Visit the Widgets tutorial to learn more about using use_imperative_handle in Pret.

    Parameters

    PARAMETER DESCRIPTION
    ref

    The ref object passed in from the parent component (via a prop).

    TYPE: Optional[RefType[T]]

    create_handle

    A function that returns the custom object/API to be assigned to ref.current.

    TYPE: Callable[[], T]

    dependencies

    Optional dependencies. If these change, the handle is re-created.

    TYPE: Optional[List] DEFAULT: None

    use_ref [source]

    Returns a mutable ref object whose .current property is initialized to the passed argument.

    The returned object will persist for the full lifetime of the component.

    If called from the Python kernel/server side, it will create a RemoteRef object, which can only be used to call methods/getters on the remote ref (no property access) and get the results as futures.

    Visit the Widgets tutorial to learn more about using refs in Pret.

    current Property

    Because refs are mutable containers whose contents can change without causing re-renders, React stores the actual value in a .current property so the ref object itself stays stable while its contents update freely.

    To keep this behavior consistent between server and client side calls to use_ref, the value of a ref is always accessed through the .current property.

    Parameters

    PARAMETER DESCRIPTION
    initial_value

    The initial value of the ref

    TYPE: T DEFAULT: None

    RETURNS DESCRIPTION
    RefType[T]

    The ref object

    use_state [source]

    Returns a stateful value, and a function to update it.

    Examples

    from pret import component, use_state
from pret.react import div, button, p


@component
def CounterApp():
    count, set_count = use_state(0)

    def increment():
        set_count(count + 1)

    return div(p(count), button({"onClick": increment}, "Increment"))

    PARAMETER DESCRIPTION

    The initial value of the state

    TYPE: T

    RETURNS DESCRIPTION
    Tuple[T, Callable[T | Callable[[T], T], None]]
    • The current value of the state
    • A function to update the state

    use_store_history [source]

    Give a component undo and redo controls for its Store in this browser page.

    Widgets using the same Store share these controls. Reloading the page clears both stacks, and edits from other pages do not enter this page's undo history.

    RETURNS DESCRIPTION
    object

    Undo and redo methods, canUndo and canRedo flags, and pending and connection status

    Can be used as @component or @component(). Pass memo=True to memoize the element . This means that if every prop stays identical (as referentially equal) between two consecutive renders, the second render won't call the function and will reuse its last output instead.

    create_store [source]

    Create a new store that can be used to store and synchronize data between various components of the app, between a server and its clients, or between different processes (or across multiple runs of the app) using a file.

    Parameters

    PARAMETER DESCRIPTION
    data

    Initial data to store in the document. It can be a dictionary, list, or any simple value. If a callable is provided, it will be called to get the initial data. This can be useful if the initial data is expensive to create, and you only want to create it if the store is actually being initialized with it (e.g. when using file synchronization and the file doesn't already exist).
    dataframe_sync

    Paged queries by default, or full to copy every SQLite table to connected browsers

    DEFAULT: 'paged'

    dataframe_max_bytes

    Required positive Arrow byte limit for the initial full copy download

    DEFAULT: None

    sync

    There are three options for this parameter:

    • If false, this store will not be synchronized between a server and its clients. This can be useful for local-only stores, like style management.
    • If true, the store will be synchronized between a server and its clients. Any changes made to the store will be sent to the server and vice versa.
    • If a path is provided, the store will be synchronized with the file at this path. Any changes made to the store will be written to the file, and any changes made to the file will be read into the store. This can be useful if you want to persist the store to disk or share it between different processes (think servers or kernels).

    TYPE: Optional[Union[bool, str, PathLike]] DEFAULT: None
